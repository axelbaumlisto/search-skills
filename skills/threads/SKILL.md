# Threads

Официальный API Meta (`graph.threads.net`). Бесплатный, **бизнес-аккаунт не нужен** —
личный работает через режим Threads Tester без App Review.

```bash
T=~/.pi/agent/skills/threads/scripts/threads.py

$T search "vibe coding" --limit 20        # поиск, TOP по умолчанию
$T search "агенты" --type RECENT          # свежее вместо популярного
$T search "llm" --raw                     # сырой JSON

$T me                                     # свой профиль и user_id
$T posts --limit 10                       # свои последние посты
$T limit                                  # остаток суточной квоты

$T post "текст" --dry-run                 # показать, что уйдёт
$T post "текст"                           # опубликовать
$T post "второй шаг" --reply-to <id>      # продолжение треда
$T post "текст" --image https://...       # картинка (только публичный URL)

$T refresh                                # продлить токен на 60 дней
```

## Лимиты, которые важны

| Что | Сколько |
|---|---|
| Текст поста | **500 символов**; эмодзи считаются байтами UTF-8 |
| Публикаций | 250 за скользящие 24 часа |
| Ответов | 1000 за скользящие 24 часа |
| Вызовов API | `4800 × показы` в сутки, минимум 48 000 |
| Токен | 60 дней, продлевается `refresh` |

## Как устроена публикация

Два шага, одним запросом нельзя:

```
POST /{user_id}/threads          → создать контейнер, получить creation_id
        ↓ подождать ~30 секунд
POST /{user_id}/threads_publish  → опубликовать контейнер
```

Пауза обязательна: сервер обрабатывает контейнер асинхронно, немедленная
публикация возвращает ошибку. Скрипт ждёт сам.

Тред собирается цепочкой: публикуешь первый пост, берёшь его `id`,
следующий постишь с `--reply-to <id>`, и так далее.

## Настройка (делается один раз, ~15 минут)

Всё в браузере под своим аккаунтом Meta. Итог — файл `~/.config/threads/env`:

```env
THREADS_USER_ID=<id из шага 4>
THREADS_ACCESS_TOKEN=<долгоживущий токен, начинается на TH>
THREADS_APP_SECRET=<нужен только для обмена и продления токена>
```

**1. Создать приложение** — https://developers.facebook.com/apps/ → «Создать».
Сценарий использования выбрать **«Доступ к Threads API»**.
Бизнес-портфель: «пока не связывать».

- Имя приложения **не должно содержать** META, FB, Face, Book, Insta, Gram — отклонит.
- Сценарий использования **потом не поменять**: ошибся — удалять приложение и заводить заново.

**2. Добавить себя тестером** — App Dashboard → «Роли приложения» → «Роли» →
«Добавить пользователя» → в блоке **«Другие роли»** выбрать **«Тестировщик Threads»**,
ввести свой username в Threads без `@`.

Обычный «Тестировщик» из верхней части окна не подойдёт — нужен именно Threads-вариант.

**3. Принять приглашение** — в Threads: Settings → More settings →
**Website permissions** → вкладка **Invites** → Accept.
Прямой адрес: `https://www.threads.com/settings/website_permissions`
(на `threads.net` этот путь отдаёт 404).

**4. Включить права** — App Dashboard → «Сценарии использования» → «Доступ к Threads API»
→ «Настроить» → «Разрешения и функции». Нужны:

- `threads_basic` — обычно уже есть;
- `threads_content_publish` — **надо нажать «+ Добавить» вручную**, иначе токен будет без права публикации;
- `threads_keyword_search` — если нужен поиск.

**5. Получить токен** — App Dashboard → «Тестирование» → «Открыть инструмент Graph API».

Главная ловушка: слева от поля URL стоит селектор API, по умолчанию `.facebook.com/`.
**Переключить на `.threads.net/`** — только тогда кнопка справа станет
«Generate Threads Access Token», а в правах появятся `threads_*`.

Нажать кнопку, пройти OAuth. Получится короткий токен на 1 час.
Проверить: в поле URL ввести `me?fields=id,name` → вернётся твой `id`, он и нужен.

Токен Threads начинается на `TH`. Если начинается иначе — селектор не переключён.

**6. Обменять на долгоживущий** (60 дней вместо часа):

```bash
curl "https://graph.threads.net/access_token?grant_type=th_exchange_token\
&client_secret=<APP_SECRET>&access_token=<КОРОТКИЙ_ТОКЕН>"
```

`APP_SECRET` — там же, «Настройки» → «Показать» (спросит пароль от Meta).

**7. Записать в файл:**

```bash
mkdir -p ~/.config/pi-skills/threads
cat > ~/.config/pi-skills/threads/env <<EOF
THREADS_USER_ID=...
THREADS_ACCESS_TOKEN=TH...
THREADS_APP_SECRET=...
EOF
chmod 600 ~/.config/pi-skills/threads/env
```

Проверить: `threads.py me` вернёт профиль.

## Грабли

| Симптом | Причина |
|---|---|
| В правах нет ни одного `threads_*` | селектор API не переключён на `.threads.net/` |
| Токен не начинается на `TH` | то же самое |
| Публикация отдаёт ошибку прав | `threads_content_publish` не добавлен вручную |
| Приглашения не видно в Threads | вошёл не тем аккаунтом, который приглашал |
| `threads.net/settings/website-permissions` → 404 | верный адрес на `threads.com`, через More settings |
| Публикация сразу после создания контейнера падает | не выдержана пауза ~30 секунд |
| Токен протух через час | короткий не обменяли на долгоживущий |
| Поиск отдаёт ошибку прав | нет `threads_keyword_search` |

## Родственные скиллы

`telegram-search` — поиск в Telegram · `marketplace-search` — Facebook Marketplace ·
`google-places` — реальные заведения · `search-agent` — роутер по всем источникам.

## Граница тестового режима (проверено 17.09.2026)

`Ready for testing` у прав означает **только свои данные**. Проверено на живом
токене:

| запрос | результат |
|---|---|
| `me`, `me/threads` | работает, свои посты отдаёт |
| `keyword_search` по слову из своего поста | 1 пост — свой |
| `keyword_search` по `danang`, `coffee`, `cafe` | пустой `data`, **без ошибки** |

Пустой ответ без ошибки — не баг запроса, а режим доступа. Публичный поиск по
чужим постам требует App Review на `threads_keyword_search` (Advanced access),
а тот требует верификации бизнеса и скринкаста.

Что доступно без App Review: чтение и публикация **своего** аккаунта. Этого
хватает для постинга и аналитики своих постов.

Для чтения чужого публичного контента Threads — браузерный путь через
`browser-scout`, API тут не поможет.
