# Zalo: чтение переписки

## Где живёт сессия — это главное

Zalo Web **не в обычном Chrome**. Ни локальный Chrome, ни `chrome-vnc` на
удалённом хосте в Zalo не залогинены: `chat.zalo.me` там отдаёт экран с QR.
Живая сессия — в **cloak-браузере** (`~/.cloakbrowser/...`, профиль
`~/.config/cloak-profile`, CDP `127.0.0.1:9444`, дисплей `:1`).

Скрипт сам поднимает ssh-туннель `9445 → 9444` и цепляется к уже открытой
вкладке. Искать заново не надо — это и есть ответ на вопрос «где Zalo».

## Команды

```bash
Z=~/.pi/agent/skills/zalo/scripts/zalo.mjs

node $Z list                 # 15 последних диалогов: имя · время · превью
node $Z list 40
node $Z read "Hương Giang"   # открыть диалог и выгрузить последние 40 строк
node $Z read "Trang Ngo" 80
node $Z read "Lift Team" 60 10   # 3-й аргумент — сколько раз прокрутить историю вверх
                                 # (без него виден только последний экран, ~неделя)

# выгрузить ВСЕ картинки чата файлами (чеки, скрины, фото документов)
node $Z imgs "Lift Team"            # 30 самых свежих → ~/Downloads/zalo/
node $Z imgs "Lift Team" 10         # только 10 свежих
ZALO_DOWNLOAD_DIR=/tmp/x node $Z imgs "Lift Team"
node $Z search "thuê nhà"    # поиск по сообщениям во всех чатах и группах
node $Z find "cọc"           # быстрее, но только по превью списка диалогов
node $Z tabs                 # что открыто в cloak-браузере

# файлы из диалога (с 14.10.2026)
node $Z files "Khánh Vân Thiên Bình"      # список вложений: имя + размер, свежие сверху
node $Z get "Khánh Vân Thiên Bình"        # скачать самый свежий -> ~/Downloads/zalo/
node $Z get "metal team" 3                # скачать третий сверху
node $Z text "Trang Ngo" 2                # скачать + напечатать текст вложения
node $Z text "Trang Ngo" 2 3000           # ограничить вывод 3000 символов
ZALO_DOWNLOAD_DIR=/tmp/x node $Z get "..." # другая папка

# картинки и фото-альбомы (с 27.10.2026)
node $Z photos "Trang Ngo"                # список фото в видимой части, 1 = самое свежее
node $Z getimg "Trang Ngo"                # скачать самое свежее фото целиком
node $Z getimg "Trang Ngo" 2              # второе сверху
ZALO_DOWNLOAD_DIR=/tmp/x node $Z getimg "..." # другая папка

### Грабли, на которые уже наступали

- **История не грузится сама.** Zalo виртуализирует ленту: без скролла `read`
  видит только последний экран (обычно 5–7 дней). Передай 3-й аргумент —
  число прокруток вверх (`read "Чат" 60 10`).
- **Картинки ленивые.** Фото в самом низу ленты попадает в DOM только после
  скролла и паузы. Поэтому `imgs` сначала крутит вниз, потом вверх шагами;
  если искать чек «вручную» через `photos`/`getimg`, он легко теряется.
- **Вкладка живёт между запусками.** Флаги и кэш в DOM сохраняются: `imgs`
  снимает свои метки при старте, свои временные атрибуты в скриптах тоже чисти.
- **Вложения `.doc` (Word 97) не читаются** через `text`: это бинарник, не zip.
  Скачивай через `get` и разбирай локально `textutil -convert txt` (macOS).

# следилка: показывает только НОВОЕ с прошлого запуска
node $Z watch                                   # по всем чатам
node $Z watch "Trung,Toàn Phát,Thuỳ Linh"       # только по этим
node $Z watch "Trung,Toàn Phát" --full          # зайти в чаты и показать живой текст

# отправка (с 04.10.2026)
node $Z send "Имя чата" "текст одной строкой"
printf 'строка 1\nстрока 2' | node $Z send "Имя чата" -     # многострочно, из stdin

node $Z unsend "Имя чата"     # отозвать ПОСЛЕДНЕЕ своё сообщение (Thu hồi)

# второй аккаунт — отдельный профиль cloak-браузера
node $Z list --acc 2
node $Z read "Tuấn Hiệp" 40 --acc 2
ZALO_ACC=2 node $Z search "tủ bánh"
```

## Скачивание файлов: только через CDP, и файл падает на удалённый хост

Zalo расшифровывает вложение **в браузере** и отдаёт нативной загрузкой. Отсюда
три тупика, которые проверены и повторять их не надо:

| подход | результат |
|---|---|
| взять `href` у кнопки скачивания | его нет — скачивание висит на JS-обработчике |
| перехватить `URL.createObjectURL` / `a.click()` с `blob:` | хук не срабатывает: blob рождается вне страничного контекста |
| вытащить ссылку из React-props сообщения | в props нет ни одного URL файла |
| `page.waitForEvent('download')` | событие приходит, но `download.path()` → `canceled`: контекст чужой, `acceptDownloads` в `connectOverCDP` не выставить |

Рабочий путь один: **разрешить загрузку напрямую по CDP**

```js
const cdp = await page.context().newCDPSession(page);
await cdp.send('Browser.setDownloadBehavior',
  { behavior: 'allow', downloadPath: '/tmp/zalo_dl', eventsEnabled: true });
```

затем клик по `.file-message__actions.download`, ожидание
`Browser.downloadProgress` со `state: completed` — и файл лежит **на хосте
cloak-браузера**, не локально. Оттуда он забирается по `scp` и удаляется с хоста.

Имя файла берётся из `Browser.downloadWillBegin.suggestedFilename` — во
вьетнамских именах есть пробелы, скобки и диакритика, поэтому в `scp` путь
экранируется, а не подставляется голым.

Нумерация в `get` идёт **с конца**: `1` — самое свежее вложение. Видны только
файлы в отрисованной части диалога: Zalo подгружает историю лениво, и старое
вложение сначала надо пролистать.

## Разбор содержимого: команда `text`

`text "<чат>" [n] [макс.символов]` скачивает n-е вложение и сразу печатает его
содержимое. Разбор локальный, без внешних сервисов:

| формат | чем разбирается |
|---|---|
| `.pdf` | `pdftotext -layout` (текстовый слой; скан вернёт пусто) |
| `.docx` | `unzip -p … word/document.xml` + снятие тегов, `<w:p>` → перевод строки |
| `.xlsx` | `unzip -p … xl/sharedStrings.xml` (только строки, без структуры листа) |
| `.txt` / `.csv` / `.md` | как есть |

Границы: сканы и фото документов текста не дают — для них есть `getimg`
и распознавание глазами. Вложения старше видимой части диалога сначала надо
прокрутить: скрипт смотрит только отрисованный DOM.

## Картинки: только через просмотрщик

Фото в Zalo Web — не файл и не ссылка. В ленте это
`<div class="photo-message-v2">` с миниатюрой 160–300 px, полноразмер рождается
**только в просмотрщике как `blob:`** после клика по пузырю. Отсюда три следствия,
которые проверены:

| что пробовали | результат |
|---|---|
| `files` / `get` на фото | пусто: download-кнопки у фото нет, только у документов |
| взять `src` миниатюры | `https://s160-26-ava-talk.zadn.vn/...` — 160×160, превью |
| подменить префикс размера (s720, s1080) | хост не существует, DNS 000 |
| искать `background-image` в пузыре | там эмодзи-спрайт, фото лежит в `<img class="zimg-el">` |

Рабочий путь (команда `getimg`): клик по `.photo-message-v2` → в просмотрщике
`fetch(blob).arrayBuffer()` → base64 → файл **локально**, без scp. Просмотрщик
показывает **галерею чата**, то есть несколько `blob:` сразу, поэтому в base64
забирается одна картинка — та, чей центр ближе к центру окна. Иначе в папку
падают чужие фото из того же чата.

Закрывается просмотрщик клавишей `Escape`; после этого DOM ещё держит старые
blob, поэтому фильтр по видимости (`getBoundingClientRect`) обязателен.

## Два аккаунта

Одним профилем два аккаунта держать нельзя: Zalo Web хранит сессию в куках
профиля, второй логин выкидывает первый. Поэтому второй аккаунт — **отдельный
экземпляр cloak-браузера** со своим профилем и портом.

| аккаунт | профиль на хосте | CDP | туннель |
|---|---|---|---|
| 1 (по умолчанию) | `~/.config/cloak-profile` | 9444 | 9445 |
| 2 (`--acc 2`) | `~/.config/cloak-profile2` | 9446 | 9447 |

Второй браузер держит user-служба `cloak-zalo2` на хосте (`Restart=always`, CDP 9446):

```bash
ssh "$ZALO_SSH_HOST" 'systemctl --user status cloak-zalo2'    # жив?
ssh "$ZALO_SSH_HOST" 'systemctl --user restart cloak-zalo2'   # поднять
```

**Не запускать профиль руками и не жать «Open in app / Install» в окне Zalo**: так
браузер стартует как приложение без `--remote-debugging-port`, порт 9446 пропадает,
и `--acc 2` молча не видит аккаунт (так и было до 08.10.2026). Если окно уже открыто
вручную — закрыть (`kill -TERM`), удалить `~/.config/cloak-profile2/Singleton*`,
`systemctl --user start cloak-zalo2`; сессия в профиле сохраняется, QR не нужен.

**«Проверь новые сообщения» = оба аккаунта**: `watch` и `watch --acc 2`.

Логин — один раз по QR через VNC (`https://clipshot.cc/vnc/`), дальше сессия
живёт в профиле.

Имя диалога ищется по видимому тексту, достаточно куска: `read "Chợ Đồ Cũ"`.

**Отправка.** Поле ввода — это сам `#richInput` (атрибут `contenteditable` висит
на нём, а не на потомке); если искать потомка, клик не находит цель. Перенос
строки внутри сообщения — `Shift+Enter`, отправка — `Enter`. Многострочный текст
удобнее слать через stdin с `-`, иначе кавычки в шелле съедают переносы.
Безопасная цель для проверки — `My Documents` (заметки себе, человека не трогает).

**Отзыв сообщения не работает — это ограничение веб-клиента, а не скрипта.**
Содержимое пузыря закрыто слоем `div_DisabledTargetEventLayer`, который гасит
события; внутри строки сообщения есть ровно два интерактивных узла — этот слой и
кнопка реакции `btn_SentMsg_React`. Кнопки «ещё» нет. Проверено правым кликом по
тексту, по `message-frame`, по `bb_msg_id`, долгим нажатием, `Shift+F10`, двойным
кликом, доверенными событиями через CDP и эмуляцией фокуса — подстроки `Thu hồi`
нет во всём DOM ни разу. Отзыв доступен только в Zalo PC и в мобильном приложении.
Команда `unsend` оставлена: падает с понятной ошибкой, ничего не трогает, и
заработает сама, если Zalo вернёт меню в вёрстку.

**Писать людям только по прямой команде владельца.**

## Границы поиска

`search` использует штатную строку Zalo Web (`#contact-search-input`), поэтому
наследует её ограничение: **веб-клиент держит историю примерно за две недели**,
в выдаче так и написано — «Sử dụng ứng dụng Zalo PC để tìm tin nhắn trước ngày …».
Более старое ищется только в десктопном Zalo PC, из браузера — никак.

Выдача чистится от мусора интерфейса: чипы фильтров `Tất cả · Chưa đọc`,
панель стикеров (`/-strong`, `:>`), баннер про Zalo PC и дубли узлов DOM.
Если Zalo поменяет вёрстку, ломаться будет именно этот фильтр.

## Вступить в группу по ссылке zalo.me/g/…

Страница `zalo.me/g/<код>` в браузере после пары открытий показывает «Kiểm tra bảo mật»
(проверка на бота) — скриптом её не проходить, это риск для аккаунта. Рабочий путь —
внутри самого веб-клиента, без капчи:

1. Отправить ссылку себе в «My Documents» (облако, никому не уходит).
2. Кликнуть по ней в чате → карточка «Thông tin nhóm / cộng đồng»: название,
   число участников, описание → «Tham gia».
3. Открытая группа — сразу внутри; «cộng đồng» с модерацией — тост
   «Yêu cầu của bạn đã được gửi đến trưởng/phó cộng đồng chờ xét duyệt», ждать одобрения.
4. После вступления: ⋯ группы → «Tắt thông báo».

Вступать по одной, с паузами, и только с согласия владельца.

## Что скрипт не делает

**Скачивает картинки** командой `getimg` (с 27.10.2026), документы — `get`,
печатает текст вложений — `text`.

**Отправляет сообщения** командой `send` (с 04.10.2026). Писать людям —
**только по прямой команде владельца**, безопасная цель для проверки — `My Documents`.
текст ответа готовится в чате с пользователем, отправляет он сам.

## Грабли

- **Туннель.** `pgrep -f "9445:127.0.0.1:9444"` — если процесс есть, скрипт его
  переиспользует. Порты берутся из `SKILLS_CONFIG` (`cloakBrowser.cdpRemotePort`,
  `cdpLocalPort`), хост — из `remoteBrowser.sshHost`.
- **playwright** ищется в `~/work/search-skills/node_modules`, потом глобально. Нет — `cd ~/work/search-skills && npm i`.
- **Сессия Zalo Web короткая.** Отдаёт `id.zalo.me/account` с QR — значит вышла.
  Восстановление только руками: открыть `chat.zalo.me` в cloak-браузере через
  VNC и отсканировать QR телефоном. Из скрипта это не решается.
- **Селекторы**: список — `#conversationList`, открытый чат — `#chatViewContainer`.
  Zalo на React-virtualized: в DOM только видимая часть, поэтому `list` отдаёт
  столько, сколько прогружено; для длинной истории чат надо проматывать.
- **Мусор в выводе.** Панель стикеров попадает в `innerText` (`/-strong`, `:>`,
  `:-((`) — фильтруется регуляркой в `read()`, но если Zalo поменяет разметку,
  первое, что сломается, это она.
- Вкладку `chat.zalo.me` в cloak-браузере **не закрывать** — второй такой
  сессии нет, повторный вход стоит QR с телефона.

## Следилка `watch`

Помнит последнее превью каждого чата в `~/.cache/zalo-watch-<аккаунт>.json`
и показывает только то, что изменилось. Свои же сообщения (`Bạn:`) не считает
ответом. Фильтр — куски имён через запятую.

Зачем: не перечитывать всю переписку, когда ждёшь ответ от нескольких поставщиков.

С `--full` по каждому новому чату скилл заходит внутрь и достаёт **настоящие
последние строки**, а не превью. Превью обрезано многоточием, и цена или габарит
из ответа поставщика туда не влезают — ради этого флаг и сделан.

### Уведомление в Telegram

`scripts/zalo-notify.sh "фильтр"` — если есть новое, шлёт сводку себе в Избранное
через Telegram-отправитель из окружения (`TG_SEND_DIR`, `TG_ENV_FILE`, `TG_SESSION`).
Молчит, когда нового нет. В cron раз в 15 минут:

```
*/15 * * * * ~/work/search-skills/skills/zalo/scripts/zalo-notify.sh "Trung,Toàn Phát,Thuỳ Linh"
```

Сессию брать рабочую: с разлогиненной скрипт падает с `not authorised`.

**Ловушка.** Zalo ставит в именах и превью **неразрывные пробелы** (`\u00a0`).
Без нормализации фильтр по обычному пробелу не совпадает никогда — это уже
ломалось. В `watch` нормализация есть, в новых командах не забывать.

## Хост и конфиг

Хост для ssh-туннеля берётся из `ZALO_SSH_HOST`, иначе из `SKILLS_CONFIG`
(`remoteBrowser.sshHost`), иначе дефолт `remote-browser`. В репозитории имён


## Ловушки Zalo Web (проверено на живой сессии 30.10.2026)

**Названия чатов содержат невидимые символы** — zero-width space, NBSP. «Diep Chi» в
списке и искомая строка `Diep Chi` побайтово не равны, поэтому наивное сравнение даёт
«диалог не найден», хотя чат есть. Сравнивать после `replace(/[\u200b-\u200f\uFEFF\u00a0]/g,'')`,
без пробелов и в нижнем регистре.

**Список виртуализирован.** `.conv-item` переиспользуются, порядок меняется, клик по
координатам строки попадает в соседнюю — так открывался `Bar counter` вместо личного
чата. Брать сам `.conv-item-title__name`, его координаты и кликать сразу после чтения,
затем сверять `.header-title`. `openChat` так и делает и падает с ошибкой, если открылся
не тот чат (лучше отказ, чем чтение чужой переписки под чужим именем).

**Панель поиска заменяет `#conversationList` целиком.** После поиска строк в DOM нет, и
следующая команда решает, что диалога не существует. Перед чтением и после каждой
команды — `resetUi`: `Escape` → кнопка `Đóng` → вкладка `Tất cả` → очистить
`#contact-search-input` → прокрутить список в начало.

**Вкладки поиска ищут разное:** `Liên hệ` — контакты, `Tin nhắn` — вхождения в текст
сообщений (в выдаче «Le Anh Son: ...», а не чаты), нужен список диалогов — держать `Tất cả`.
Выдача тоже прокручивается, без прокрутки нужная строка может быть не отрисована.

**`getimg`/`photos` открывают просмотрщик-альбом** и отдают blob картинки, ближайшей к
центру экрана, а не обязательно нажатой — так скачивались чеки Thiên Bình вместо чеков
из личного чата. После клика сверять пропорции blob с размерами пузыря (`naturalWidth`/
`naturalHeight`), что `downloadPhoto` теперь и делает.
